# OSINT & Investigative Workflow Study

## Project Type
Open-source research / investigative analysis / documentation workflow

## Mission Objective
Develop a professional, ethical, and repeatable workflow for open-source research and investigative analysis using publicly available information.

The purpose is not unauthorized access, exploitation, harassment, bypassing controls, or private account access. The purpose is to practice structured research, source validation, documentation, timeline reconstruction, and analytical reporting in a way that can support IT operations, legal operations, compliance, fraud review, security support, and investigative analyst work.

## Ethical Boundaries

### Allowed Research Areas

- Public websites
- Public company pages
- Public social media profiles
- Public news sources
- Public technical documentation
- Public breach reports or advisories
- Public government databases
- Search engine results
- Public GitHub repositories
- Public domain and website records

### Off-Limits Activity

- Unauthorized login attempts
- Password guessing
- Bypassing access controls
- Private account access
- Social engineering
- Malware
- Exploitation
- Harassment

## Core Workflow

### 1. Define the Research Question

Before collecting information, define the exact objective.

Examples:

- What happened?
- Who or what is involved?
- When did the event occur?
- What systems, accounts, companies, or public sources are relevant?
- What is verified versus assumed?

### 2. Establish Scope

Define what sources are allowed and what boundaries apply.

Scope keeps the research professional and prevents wandering into irrelevant or inappropriate areas.

### 3. Collect Initial Leads

Start broad, then narrow.

Potential source categories:

- Search engines
- Company websites
- LinkedIn
- Public GitHub repositories
- Public documentation
- News articles
- Government records
- Public court records
- WHOIS / domain information
- Technical forums

### 4. Validate Sources

Each source should be reviewed for credibility.

Questions:

- Is this a primary source?
- Is it current?
- Can another source confirm it?
- Is the source official, user-generated, or speculative?
- Is the information direct evidence or commentary?
- Is there any conflict of interest?

### 5. Build a Timeline

When time matters, organize findings chronologically.

| Date | Event | Source | Confidence |
|---|---|---|---|
| YYYY-MM-DD | Event description | Source note | High / Medium / Low |

### 6. Separate Facts, Assumptions, and Unknowns

A strong investigation does not pretend guesses are facts.

```md
## Verified Facts
- Fact 1
- Fact 2

## Assumptions
- Assumption 1
- Assumption 2

## Unknowns
- Unknown 1
- Unknown 2

## Next Questions
- Question 1
- Question 2
```

### 7. Analyze Patterns

Look for meaningful relationships without overreaching.

Pattern examples:

- Repeated names
- Repeated domains
- Repeated usernames
- Matching timestamps
- Shared infrastructure
- Similar language
- Repeated business addresses
- Common tools or platforms

### 8. Write the Report

Final report structure:

```md
# Investigation Summary

## Objective
What question was being investigated?

## Scope
What sources were reviewed and what boundaries were followed?

## Key Findings
Most important verified findings.

## Timeline
Chronological event list.

## Supporting Evidence
Sources and notes.

## Assessment
What the findings suggest.

## Confidence Level
High, medium, or low confidence.

## Unknowns
What still needs verification.

## Recommended Next Steps
What should be done next.
```
